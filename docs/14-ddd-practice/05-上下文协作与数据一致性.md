# 05｜上下文协作与数据一致性：调用、ACL、事件和 Outbox 怎么选

## 本篇目标

把跨上下文协作拆成四个问题：谁拥有事实、谁负责翻译、调用方需要什么时效、失败后如何恢复。不要把所有跨模块交互都变成 MQ。

## 1. 先确定数据所有权

案例约定：

- 线索上下文拥有 Lead 状态和分配规则。
- 销售任务上下文拥有 FollowUpTask 生命周期。
- 客户预警上下文拥有 Alert 生命周期。
- 报表上下文拥有自己的查询投影。

其他上下文不能直接修改 Lead 表。共享数据库不代表共享业务写权限。

## 2. 同步调用还是异步事件？

| 判断条件 | 同步调用更合适 | 异步事件更合适 |
|---|---|---|
| 当前请求是否必须立即得到结果 | 是 | 否 |
| 是否需要读取对方实时决策 | 是 | 通常否 |
| 是否允许短暂延迟 | 否 | 是 |
| 对方不可用时是否允许稍后完成 | 否 | 是 |
| 是否是已经发生、需要通知多个消费者的事实 | 不一定 | 是 |

不要用事件代替需要即时返回的业务校验，也不要用同步 HTTP 串起可以独立完成的长流程。

## 3. ACL：翻译外部语义，而不只是改字段名

假设外部销售系统返回状态 20。不能直接猜它等于本地 FOLLOWING。

正确流程：

~~~text
External Sales Contract
      |
      v
External DTO
      |
      v
Translator / ACL
  - 解释外部状态语义
  - 处理未知值和缺失值
  - 映射到本地概念
      |
      v
Local SalesStatus
~~~

如果只是字段名和嵌套结构变化，普通 Mapper 足够。只有外部模型的语义、规则或生命周期与本地不同，需要保护本地模型时，才需要 ACL。

ACL 通常靠近要保护自己模型的一侧。它可以是应用入口适配器，也可以是基础设施适配器；不是必须放在 Domain 层，更不意味着必须独立部署。

## 4. 领域事件与集成事件

- 领域事件：本上下文内部表达业务事实。
- 集成事件：跨上下文发布的稳定契约。

例如 Lead 聚合成功分配后产生 LeadAssigned。应用层可以将其映射为对外的 LeadAssignmentCompletedV1。领域事件和集成事件不要求一一对应。

集成事件需要明确：

~~~text
eventId
eventType
schemaVersion
occurredAt
aggregateId
payload
traceId / correlationId（按需）
~~~

事件应描述已经发生的事实，不要发布“请把线索分配给某人”这种命令并伪装成事件。

## 5. Outbox 解决什么，不解决什么？

问题：数据库事务提交成功，但 MQ 发布失败；或者 MQ 已发布，数据库事务回滚。

Outbox 把业务数据变更和待发布事件写入同一个本地数据库事务：

~~~text
BEGIN
  UPDATE lead ...
  INSERT INTO outbox_event ...
COMMIT
       |
       v
Publisher 扫描待发送事件
       |
       v
发送 MQ
       |
       v
标记已发送 / 记录重试
~~~

它保证“业务变更”和“待发布记录”在同一个本地事务中提交，不等于端到端 exactly-once。发布器可能重复发送，消费者必须幂等。

## 6. 消费者幂等

常见做法是消费者在自己的本地事务中：

~~~text
BEGIN
  INSERT processed_event(event_id)  -- 唯一约束
  UPDATE projection ...
COMMIT
~~~

如果 event_id 已处理，安全地忽略重复事件。若处理包含外部副作用，必须单独设计幂等键和补偿机制，不能只依赖一张去重表。

## 7. 顺序、重试和死信

需要回答：

- 同一个 Lead 的事件是否必须有序？
- 事件是否带 aggregateVersion？
- 消费者遇到旧版本事件如何处理？
- 重试是否可能导致重复副作用？
- 超过重试次数后进入哪里？
- 谁负责告警、人工修复和对账？

如果需要按聚合顺序处理，可以使用聚合 ID 作为消息分区键，并在消费者检查版本；具体方案取决于消息系统能力和吞吐要求。

## 8. 何时使用 Canonical Data Model？

多数据源接入平台可能需要规范数据模型，但它不等同于 DDD 领域模型。

- Canonical Model：跨数据源或系统交换的稳定契约。
- Domain Model：某个上下文内部表达业务规则的模型。
- ACL：把外部语义翻译成本地语义的边界。
- Mapper/Normalizer：结构、格式和类型归一化。

不要让一个包含任意 Map 的万能 DTO 成为所有领域共享模型。

## 本篇决策卡

| 问题 | 优先考虑 |
|---|---|
| 请求必须即时获得对方结果 | 同步查询/命令 |
| 外部语义污染本地模型 | ACL |
| 只需字段结构转换 | Mapper |
| 发布已发生的业务事实 | Integration Event |
| DB 事务与消息发布必须可靠衔接 | Outbox |
| 消费者可能收到重复事件 | 幂等 |
| 读模型允许短暂延迟 | 异步投影 |
| 多数据源结构归一 | Normalizer + Canonical Contract |

**口诀：先明确事实归谁，再选择通信方式；先保证本地事务，再设计跨系统恢复。**
