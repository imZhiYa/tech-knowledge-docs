# 📨 MQ 系列：从"为什么存在"到生产问题急诊

**消息队列（RocketMQ / Kafka / RabbitMQ / Pulsar）通用机制全链路：为什么存在 → 队列 vs 日志 → 存储 → 投递语义 → 顺序幂等 → 消费模型 → 扩容 → 异常机制 → 高可用 → 选型 → 生产问题。**

> 主线比喻：一座城市货运中转站。Message E 的一生 = 诞生 → 分拣 → 落账 → 签收 → 重发 → 取件 → 改组 → 异常件 → 车队 → 总控 → 急诊，十一篇唯一比喻。

## ⚠️ 版本与证据边界（系列统一）

| 产品 | 基线 |
| ---- | ---- |
| Apache RocketMQ | 5.x（对比 4.9.x） |
| Apache Kafka | 3.5.x KRaft（对比 2.8.x ZK 模式） |
| RabbitMQ | 3.13.x（AMQP 0-9-1 + quorum queue） |
| Apache Pulsar | 3.x（对比层：存算分离架构） |

铁律：

- 不把"MQ"等同于某一个产品；同一机制落到四个产品的实现上对照
- 规范层（AMQP 0-9-1、投递语义三分类）与实现层（各 Broker 行为）分开陈述
- Kafka 2.8.x → 3.5.x 区分语义变化（元数据管理 ZK → KRaft）与代码组织变化
