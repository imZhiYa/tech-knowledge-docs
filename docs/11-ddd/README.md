# 🏛️ DDD 系列：从"为什么需要领域边界"到生产决策

**领域驱动设计（DDD）全链路：为什么存在 → 统一语言与业务边界 → 上下文映射 → 实体值对象与聚合 → 一次请求如何落到代码 → 事件与最终一致性 → 生产决策与选择性 DDD。**

> 主线比喻：一座政务大厅，每个窗口只办一类业务。请求 R 的一生 = 进大厅 → 分窗口 → 跨窗口协作 → 窗口内办理 → 收据送达 → 换窗/装修决策，七篇唯一比喻。业务场景：电商首页「千人千面」推荐。

## 🔑 核心主线

- **业务场景**：电商首页「千人千面」推荐 —— 用户画像、商品目录、推荐策略、实验管理、在线决策、反馈分析六个上下文。
- **唯一主线角色**：R（推荐请求）的一生，从 ddd-00 进大厅到 ddd-06 装修决策。
- **核心机制**：聚合不变量、防腐层（ACL）契约翻译、发布语言、事件 Outbox、最终一致性、选择性 DDD。
- **版本纪律**：正文区分规范（Evans 2003 / DDD Reference 2015 / Vernon 2013）与实现（Spring/JPA 具体版本待核证）；未实测数字一律标注"待验证"。
